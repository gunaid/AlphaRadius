# قالب Proxmox جاهز للعملاء الجدد (27 نوفمبر 2026)

## الفكرة

تجهّز جهازًا افتراضيًا (VM) واحدًا عندك حيث الإنترنت جيد، فيه Ubuntu وDocker وصور النظام مبنية. تأخذ منه نسخة احتياطية من Proxmox على فلاشة. عند كل عميل تسترجع النسخة وتشغّل سكربت التشغيل الأول: لا تنزيل ولا بناء، والنظام يعمل خلال دقائق.

الطرق القديمة (`install.sh` و`deploy/local/build_and_start.sh`) لم تتغير ولا تُستخدم هنا.

| الملف | أين يعمل | ماذا يفعل |
|---|---|---|
| `deploy/proxmox/prepare_template.sh build` | VM القالب عندك (مع إنترنت) | يثبت Docker وNginx، يبني صور Web/Core/L2TP، ينزّل MariaDB وautoheal، يضع ملفات التشغيل في `/opt/alpha-radius`. **لا يشغّل النظام** ولا ينشئ قاعدة بيانات أو أسرار. |
| `/opt/alpha-radius/prepare-template.sh seal` | VM القالب، قبل النسخة الاحتياطية | يتأكد أن الجهاز نظيف، ثم يحذف هوية الجهاز (machine-id ومفاتيح SSH) وذاكرة البناء. |
| `/opt/alpha-radius/first-boot.sh` | VM العميل بعد الاسترجاع (بدون إنترنت) | ينشئ أسرار هذا العميل وكلمات مرور قاعدة البيانات العشوائية ثم يشغّل النظام من الصور المحلية. يعمل مرة واحدة فقط. |

## أولًا: تجهيز القالب (مرة لكل إصدار)

1. **في Proxmox أنشئ VM:** Ubuntu Server 24.04 ISO، معالجات 4، ذاكرة 8GB، قرص 40GB أو أكثر، شبكة virtio على vmbr0.
   نوع المعالج (CPU Type): اترك الافتراضي `x86-64-v2-AES` ولا تختر `host`. بصمة الترخيص تتضمن اسم طراز المعالج؛ مع `host` يتغير الطراز إذا نُقل الـVM لخادم آخر.
2. **ثبّت Ubuntu** مع OpenSSH Server، ثم سجل الدخول.
3. **انسخ المستودع وشغّل البناء:**
   ```bash
   sudo apt-get install -y git
   git clone https://github.com/gunaid/AlphaRadius.git ~/AlphaRadius
   cd ~/AlphaRadius && sudo bash deploy/proxmox/prepare_template.sh build
   ```
4. **انقل مفتاح التوقيع إلى جهازك واحذفه من القالب** (يجب ألا يصل لأي عميل):
   ```bash
   sudo cp /root/alpha-private/runtime-signing-private.pem ~/ && sudo chown $USER ~/runtime-signing-private.pem
   ```
   من جهازك: `scp USER@IP-القالب:runtime-signing-private.pem .` واحفظه في مكان آمن، ثم على القالب:
   ```bash
   shred -u ~/runtime-signing-private.pem && sudo shred -u /root/alpha-private/runtime-signing-private.pem
   ```
   في الإصدار القادم ضعه مكانه قبل `build` ليُعاد استخدامه.
5. **احذف الكود المصدري** (العملاء يأخذون الصور فقط):
   ```bash
   rm -rf ~/AlphaRadius
   ```
6. **ختم القالب:**
   ```bash
   sudo bash /opt/alpha-radius/prepare-template.sh seal
   ```
   يرفض إن بقي المفتاح أو الكود، أو إن كان النظام قد شُغّل على هذا الجهاز، أو إن نقصت صورة. اكتب `SEAL` للتأكيد.
7. **أطفئ الجهاز** (`sudo poweroff`) ولا تشغّله بعدها.
8. **خذ نسخة احتياطية:** في Proxmox اختر الـVM ثم Backup ثم Backup now، Mode: Stop، Compression: ZSTD. الملف يظهر في `/var/lib/vz/dump/` باسم مثل `vzdump-qemu-120-....vma.zst`. انسخه على الفلاشة.

## ثانيًا: عند كل عميل جديد

1. ثبّت Proxmox كعادتك، وانسخ ملف `vzdump-qemu-...vma.zst` من الفلاشة إلى `/var/lib/vz/dump/` على خادم العميل.
2. في Proxmox: Datacenter ثم local ثم Backups، اختر الملف ثم **Restore**، واختر رقم VM جديدًا وفعّل **Unique** (عناوين MAC جديدة).
3. **غيّر UUID الجهاز:** VM ثم Options ثم SMBIOS settings (type1)، واضغط زر توليد UUID جديد ثم OK. هذا يمنع أن يحمل كل العملاء نفس بصمة الترخيص؛ سكربت التشغيل الأول يرفض العمل إن بقي UUID القالب.
4. شغّل الـVM وادخل من Console في Proxmox.
5. **اضبط عنوان IP** للعميل: `sudo alphaip`
6. **شغّل النظام لأول مرة:**
   ```bash
   sudo bash /opt/alpha-radius/first-boot.sh
   ```
   مع منفذ مدير مستقل: `sudo bash /opt/alpha-radius/first-boot.sh --admin-port 43333`
   المنطقة الزمنية الافتراضية Asia/Aden؛ لغيرها: `--timezone Asia/Riyadh`. اكتب `START` للتأكيد.
7. افتح الرابط الذي يطبعه السكربت، غيّر كلمة مرور المدير الأولية، وفعّل الترخيص (يحتاج اتصالًا قصيرًا بخادم الترخيص أو التجديد دون اتصال). تأكد أن تاريخ الخادم ووقته صحيحان قبل التفعيل.

## ما يحمي منه السكربتان

* **أسرار مختلفة لكل عميل:** كلمة مرور قاعدة البيانات وكلمة مرور root لها وسر فحص RADIUS تُنشأ عشوائيًا في `/opt/alpha-radius/.env` (صلاحية root فقط). ملف compose يقرأها من `ALPHA_DB_PASSWORD` و`ALPHA_DB_ROOT_PASSWORD`، وقيمها الافتراضية بقيت `radpass` و`rootpass` فلا يتغير شيء للتثبيتات الحالية. لا تضف هذين المتغيرين لتثبيت قائم: قاعدة البيانات الموجودة تحتفظ بكلمة مرورها الأصلية.
* **رقم تثبيت جديد:** القالب لا يحتوي `storage/instance_id` ولا قاعدة بيانات؛ يُنشآن عند التشغيل الأول.
* **لا تنزيل عند العميل:** كل تشغيل بـ `--pull never`؛ صورة ناقصة تعطي خطأ واضحًا بدل محاولة التنزيل.
* **لا مفاتيح ولا كود في القالب:** الختم يرفض وجود مفتاح التوقيع أو نسخة من المستودع، ويحذف ذاكرة بناء Docker.
* **تشغيل أول مرة واحدة:** يرفض إعادة التشغيل أو العمل على جهاز فيه نظام أو بيانات.
* **مفاتيح SSH جديدة:** خدمة `alpha-ssh-hostkeys` تنشئها عند أول إقلاع، وmachine-id يُنشأ من جديد.

## التحديث لاحقًا

التحديث عند العميل يكون بالطرق المعتادة (بناء من الكود أو صور منشورة)، أو بقالب جديد لعميل جديد. السكربت لا يغيّر نظامًا يعمل.

## الفحوص

* `tests/test_proxmox_template.py` (معزول، Docker وهمي، 12): رفض المفتاح والكود والجهاز المستخدم والبناء الناقص والصورة الناقصة (منها L2TP)، تأكيد الختم وحذف الهوية والذاكرة، رفض UUID القالب، فحص المعاملات، أسرار عشوائية مختلفة بين جهازين وصلاحية 600، و`--pull never` في كل تشغيل، وقيم compose الافتراضية.
* تشغيل كامل محليًا مع **Docker حقيقي**: build ثم seal ثم first-boot بصور MariaDB وautoheal الحقيقية وصور بديلة صغيرة لـ Web/Core/L2TP. الخدمات الخمس healthy، والويب وCore يدخلان قاعدة البيانات بكلمة المرور العشوائية بينما `radpass` و`rootpass` مرفوضتان، ولا تنزيل أثناء التشغيل الأول، وتشغيل ثانٍ مرفوض.
* **لم يُختبر:** بناء صور Web/Core/L2TP الحقيقية داخل السكربت (نفس أوامر `build_and_start.sh`)، ولا Proxmox نفسه (النسخ والاسترجاع وتغيير UUID)، ولا `alphaip` داخل VM.
