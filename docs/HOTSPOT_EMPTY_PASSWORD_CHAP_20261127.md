# كروت الرمز الواحد مع CHAP وكلمة مرور فارغة (27 نوفمبر 2026)

## المشكلة

كروت User Manager المستوردة بكلمة مرور فارغة تُحفظ بكلمة مرور = اسم المستخدم (`services/mikrotik_userman_importer.py`)، مثل كروت الرمز الواحد التي ينشئها النظام. صفحة الدخول ترسل اسم المستخدم فقط.

* مع **PAP** كانت تعمل: قاعدة `HOTSPOT_SINGLE_FIELD_CARD_FALLBACK` في `docker/freeradius/entrypoint.sh` تجعل كلمة المرور الفارغة = اسم المستخدم.
* مع **CHAP** (الافتراضي في بروفايل هوتسبوت ميكروتك `http-chap`) لم تكن تعمل: الراوتر يرسل بصمة CHAP لكلمة مرور فارغة، والقاعدة السابقة لا تنطبق على CHAP، فتُقارن البصمة بكلمة المرور المخزنة (اسم المستخدم) ويُرفض الدخول. كروت النظام نفسها كانت ستُرفض بنفس الطريقة على صفحة كهذه.

## الإصلاح

في `Auth-Type CHAP` (يضيفه entrypoint عند تشغيل Core، مرة واحدة بالعلامة `HOTSPOT_SINGLE_FIELD_CHAP_FALLBACK`):

1. فحص CHAP العادي أولًا.
2. إن رُفض، وكان الحساب كرت رمز واحد (كلمة المرور المخزنة = اسم المستخدم)، وليس PPP: يُعاد الفحص مرة واحدة بكلمة مرور فارغة.

لا تتغير البيانات ولا حاجة لإعادة الاستيراد: الكروت المستوردة تعمل بعد تحديث Core. أي حساب كلمة مروره مختلفة عن اسمه لا يتأثر، وPPP لا يتأثر، والكلمة الخاطئة تُرفض.

## التطبيق

يحتاج إعادة بناء صورة Core (entrypoint داخل الصورة): `deploy/local/build_and_start.sh`. حل فوري دون تحديث: تفعيل `http-pap` في بروفايل الهوتسبوت على الراوتر.

## الفحوص

`tests/test_hotspot_chap_empty_password.py`: فحص التوصيل، وثلاثة فحوص على FreeRADIUS 3.2.5 الحقيقي (إن وُجد) بالإعداد الأصلي مع تعديلات entrypoint نفسها:

| الحالة | قبل | بعد |
|---|---|---|
| كرت رمز، CHAP، كلمة فارغة | Reject | Accept |
| كرت رمز، PAP، فارغة / CHAP بالاسم | Accept | Accept |
| كرت رمز، CHAP، كلمة خاطئة | Reject | Reject |
| حساب عادي، فارغة / الاسم ككلمة | Reject | Reject |
| حساب عادي، كلمته | Accept | Accept |
| كرت رمز عبر PPP، فارغة | Reject | Reject |

لم يُختبر على راوتر ميكروتك فعلي أو داخل حاوية Core المبنية.
