# الماك العشوائي: دخول مباشر ثم فصل الجلسة الخاملة — 25 نوفمبر 2026

## المشكلة
الهاتف الذي يعيد الاتصال قد يأتي بماك عشوائي جديد، وتبقى جلسته القديمة على الراوتر حتى تنتهي مهلتها. إذا كان الكرت مسموحًا له بجهاز واحد (Simultaneous-Use) كان الدخول الجديد يُرفض مع أن صاحبه هو نفسه.

## لماذا لا يُفحص الخمول داخل طلب الدخول نفسه
الراوتر ينتظر رد RADIUS جزءًا من الثانية ثم يعيد المحاولة أو يفشل الدخول. الفحص المباشر يعني أن FreeRADIUS يطلب من اللوحة، واللوحة تطلب API الراوتر نفسه وهو ينتظر الرد؛ أي تأخير في API أو اللوحة يصبح فشل دخول لكل المستخدمين. لذلك يُقبل الدخول فورًا ويجري القرار بعده.

## السلوك
1. عند بلوغ حد الأجهزة ووصول دخول بماك غير فارغ والإعداد مفعّل، تقبل `fn_reserve_license_slot` الدخول (النتيجة 1) على **مقعد إضافي مؤقت واحد فقط**، وتسجل صفًا للحساب في `wisp_roaming_requests` بحالة `pending`. لا تظهر رسالة خطأ.
   - جهاز ثالث أثناء الفحص يُرفض بالرسالة المعتادة (النتيجة 2).
   - ماك رُفض بهذا المسار خلال آخر 5 دقائق (`outcome='denied'` في `wisp_roaming_events`) يُرفض مباشرة.
   - سعة الترخيص تبقى نافذة: لا يُسجل طلب إن رُفض الدخول لبلوغ السعة.
   - الماك المدرج في [الماكات المستنسخة](CLONED_MACS_20261125.md) لا يشمله هذا المسار؛ يبقى له الحد المعتاد.
2. العامل `services/roaming_service.py` (خيط `RoamingWorker` مع تطبيق Web على MariaDB، كل ثانيتين) يحجز الطلب ذريًا ويقرأ من الراوتر عبر API (`/ip/hotspot/active/print ?user=`) قيمة `idle-time` للجلسة **القديمة**:
   - خمول ≥ `roaming_idle_seconds` (افتراضي 20، من 10 إلى 600) ← فصل الجلسة القديمة (الأكثر خمولًا) — هي الهاتف الذي غادر.
   - خمول أقل ← إعادة الفحص كل 5 ثوانٍ. الهاتف الذي غادر يزداد خموله فيصل إلى الحد سريعًا.
   - بقيت نشطة طوال `roaming_idle_seconds + 30` ثانية ← جهاز آخر يستخدم الكرت: فصل الجلسة **الجديدة** ومنع ذلك الماك 5 دقائق.
   - انتهت الجلسة القديمة بنفسها ← `freed`. غير موجودة على الراوتر (جلسة شبح) ← `absent` وتبقى الجديدة.
   - تعذر قراءة الراوتر طوال المدة، أو PPPoE ← لا فصل؛ `unverified` أو `denied` (PPPoE لا يملك idle-time فيعامل كنشط).
3. الفصل بمسار الفصل المعتاد (`enqueue_disconnect` مع IP/MAC/Session-ID/radacctid، تثبيت العدادات ثم التحقق من اختفائها من الراوتر). قبول طلب الفصل ليس Stop؛ المقعد يتحرر بـAccounting-Stop الحقيقي.
4. كل نتيجة في `wisp_roaming_events`: kicked / denied / freed / absent / unverified / queue_failed / error، مع الماك الجديد والقديم والخمول، لاستخدامها في التقارير وكشف الماكات المستنسخة.

## المقايضة
أثناء الفحص (حتى 50 ثانية بالافتراضي) يعمل الجهازان. مشاركة الكرت تمنح الجهاز الثاني هذه المدة مرة واحدة ثم يُمنع ماكه 5 دقائق. هاتف المستخدم الأصلي إذا كان خاملًا 20 ثانية (الشاشة مغلقة) قد تُفصل جلسته إن دخل جهاز آخر بالكرت؛ ارفع المدة إن كان ذلك متكررًا.

## الإعدادات
الإعدادات ← الشبكة و FreeRADIUS ← «الماك العشوائي»: تفعيل (افتراضي مفعّل) ومدة الخمول. الإيقاف يعيد الرفض المعتاد عند الحد.
يتطلب بيانات API لكل راوتر؛ بدونها تكون النتيجة `unverified` ولا يُفصل شيء، ويبقى الجهازان حتى تنتهي إحدى الجلستين.

## النشر
- تغيير `RESERVE_SQL` ترحيل سعة: يُبطل الـlease قبل DDL ثم يعيد الناشر نشره (حتى 30 ثانية رفض مؤقت عند الترقية).
- التغيير كله في Web (الجدولان والدالة والعامل)؛ لا يلزم بناء Core لهذه الميزة. `database/roaming_schema.py` مضاف إلى Dockerfile.
