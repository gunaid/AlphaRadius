# الماك العشوائي: تحرير الجلسة الخاملة — 25 نوفمبر 2026

## المشكلة
الهاتف الذي يعيد الاتصال بالشبكة قد يأتي بماك عشوائي جديد، وتبقى جلسته القديمة على الراوتر حتى تنتهي مهلتها. إذا كان الكرت مسموحًا له بجهاز واحد (Simultaneous-Use) يُرفض الدخول الجديد مع أن صاحبه هو نفسه.

## السلوك
1. عند بلوغ حد الأجهزة ووصول دخول بماك غير فارغ والإعداد مفعّل، ترجع `fn_reserve_license_slot` النتيجة **4**:
   رفض بالرسالة `fn_rmsg('roaming')` (الافتراضي `simultaneous session limit reached, retry in one minute`)
   مع إدراج/تحديث صف واحد للحساب في `wisp_roaming_requests` بحالة `pending`. **لا يُحجز مقعد** في هذا الرد.
2. العامل `services/roaming_service.py` (خيط `RoamingWorker` يبدأ مع تطبيق Web على MariaDB، كل ثانيتين) يحجز الطلب ذريًا،
   ويقرأ من الراوتر عبر API (`/ip/hotspot/active/print ?user=`) قيمة `idle-time` للجلسات المفتوحة للحساب:
   - خاملة مدة ≥ `roaming_idle_seconds` (افتراضي 45، من 10 إلى 600) ← فصل الجلسة الأكثر خمولًا بمسار الفصل المعتاد
     (`enqueue_disconnect` مع IP/MAC/Session-ID/radacctid، تثبيت العدادات ثم التحقق من اختفائها من الراوتر).
   - فيها ترافيك حي ← تبقى، ويستمر الرفض (جهاز آخر يستخدم الكرت).
   - تعذر قراءة الراوتر، أو الجلسة غير موجودة/ملتبسة على الراوتر، أو PPPoE ← لا تغيير.
3. المحاولة التالية للجهاز الجديد تنجح بعد وصول Accounting-Stop للجلسة القديمة؛ قبول طلب الفصل وحده لا يعد Stop ولا يحرر المقعد.
4. فحص واحد لكل حساب كل 5 ثوانٍ لكل عامل، ومطالبة عالقة تعاد بعد 60 ثانية. محاولة مرفوضة أحدث أثناء الفحص تعيد الصف إلى `pending`.
5. كل نتيجة تُسجل في `wisp_roaming_events` (الماك الجديد والقديم، الخمول، النتيجة: kicked/live/unverified/absent/no_session/queue_failed/error) لاستخدامها في التقارير وكشف الماكات المستنسخة.

## الإعدادات
الإعدادات ← الشبكة و FreeRADIUS ← «الماك العشوائي: تحرير الجلسة الخاملة»: تفعيل (افتراضي مفعّل) ومدة الخمول،
ورسالة الرفض `radius_msg_roaming` ضمن رسائل الرفض. إيقاف الإعداد يعيد النتيجة 2 (الرسالة المعتادة) دون طلبات.
يتطلب بيانات API لكل راوتر في صفحة الراوترات؛ بدونها تكون النتيجة `unverified` ولا يُفصل شيء.

## النشر
- تغيير `RESERVE_SQL` يُعد ترحيل سعة: يُبطل الـlease قبل DDL ثم يعيد الناشر نشره (حتى 30 ثانية رفض مؤقت عند الترقية).
- **الترتيب:** Web أولًا (تنشئ الجدولين والدالة و`fn_rmsg('roaming')`) ثم Core (فرع `== "4"` في `license-capacity-postauth.conf`).
  Core القديمة مع Web الجديدة تعرض الرسالة العامة لنتيجة 4 (`License verification…`) لأنها لا تعرف الفرع؛ الرفض نفسه صحيح.
- `database/roaming_schema.py` مضاف إلى قائمة COPY في Dockerfile.
